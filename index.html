Method

The Great Work, in four stages

Alchemists described transformation in four colours. It’s a fair map of how a messy brief becomes dependable software.

  1. Nigredo

    Understand

    Break the problem down to what’s really there: the people, the rules, the data and the constraints. Find the hard parts early.

  2. Albedo

    Clarify

    Design the data model, the API and the journeys. Write down the decisions and confirm the open questions with the client.

  3. Citrinitas

    Build

    Small, reviewed pull requests. Tests against a real database. Each step is deployed to a test environment and checked there.

  4. Rubedo

    Harden & ship

    Security scans, monitoring, backups and runbooks, then a calm release and a clean hand-over.

  • Every change is reviewed. Nothing merges without an independent review and green CI.
  • Real databases in tests. Migrations and access rules are tested, not assumed.
  • Privacy by default. Collect less, keep it shorter, and never send personal data in notifications.
  • Written down. Decisions, runbooks and hand-over notes are part of the delivery.

About

Why “Code Alchemist”

Alchemy promised to turn base metal into gold. Software has a quieter version: take a tangle of requirements, legacy systems and half-answered questions, and turn it into something that works, lasts and can be trusted.

I’ve done that inside banks, where correctness and audit trails aren’t optional, and for smaller clients who need one engineer to own the whole stack. Alchemia is the name for that independent work.

Outside client work I run a small homelab, write things down in a knowledge vault, and keep refining how humans and AI agents can build software together without lowering the bar.
